# Inno Daily Log — Obsidian 플러그인

데일리 노트의 **금일 예정 업무**를 다음 날 노트의 **전일 진행 업무**로 옮기고,
inno 업무 양식 템플릿을 삽입하며, 스크럼(scrum)에 올릴 내용만 골라 복사하는 Obsidian 플러그인입니다.

외부 API를 쓰지 않습니다. Vault 안에서만 동작합니다.

> v0.2.0 — 로컬 전용. 그룹웨어 연동은 아직 없습니다.

## 기능

### 전일 진행 업무 로드

현재 노트보다 앞선 날짜의 데일리 노트를 최신순으로 훑어, **금일 예정 업무** 섹션에
내용이 있는 첫 노트를 찾습니다. 그 내용을 현재 노트의 **전일 진행 업무** 섹션 본문으로
덮어씁니다.

- 노트 파일명에서 `YYYY-MM-DD` 를 날짜로 읽습니다 (`2026-09-01 Abraxas.md`).
- 섹션 제목은 `**[전일 진행 업무]**` 처럼 볼드 대괄호 형태여야 합니다.
  제목 뒤의 NBSP(` `)와 공백은 무시합니다.
- 섹션 본문은 다음 섹션 제목이나 `---` 를 만나면 끝납니다.
- 기존 본문의 앞뒤 빈 줄은 그대로 두고 내용만 교체합니다.

**월별 폴더를 넘어서 찾습니다.** 노트를 `Work/Daily/2026-09/` 처럼 월별로 나눠 담아도
매월 1일에 전월 노트를 정상적으로 찾습니다.

### 데일리 노트 템플릿 삽입

커서 위치에 설정된 업무 양식 본문을 삽입합니다. frontmatter 는 넣지 않으므로
코어 템플릿 플러그인이나 Templater 와 함께 써도 충돌하지 않습니다.

### 스크럼(scrum) 내용 복사

노트 안에서 마커로 감싼 영역만 원문 그대로 클립보드에 복사합니다. 데일리 노트에는
스크럼에 올릴 것과 개인 메모가 섞여 있어, 매번 드래그로 범위를 잡지 않아도 되게 합니다.

```markdown
%% inno-scrum:start %%
- 어제: 캐시 조회 API 개발
- 오늘: PR 리뷰, 배포 준비
%% inno-scrum:end %%
```

- `%% %%` 는 Obsidian 주석이라 **읽기 모드에서는 보이지 않습니다.** 소스 모드에서만 보입니다.
- 마커 줄 자체와 영역 밖 내용은 복사되지 않습니다. 들여쓰기·빈 줄·마크다운은 그대로 둡니다.
- 읽기 모드에서도 복사됩니다.
- 마커 문자열은 설정으로 바꿀 수 없습니다. 바꾸면 기존 노트의 영역이 전부 깨집니다.

**서식이 살아서 붙습니다.** 클립보드에 렌더된 HTML 과 마크다운 원문을 함께 담으므로,
붙여넣는 쪽이 알아서 고릅니다.

| 붙여넣는 곳 | 들어가는 것 |
|---|---|
| Teams·Slack·Confluence·워드·메일 | 렌더된 서식 (굵게·링크·표·중첩 목록) |
| 코드 편집기·터미널·다른 마크다운 앱 | 마크다운 원문 그대로 |

서식까지 담지 못한 경우(창이 비활성이거나 지원하지 않는 환경)에는 알림이
"서식 없이 마크다운 원문만 담았습니다" 로 바뀝니다. 조용히 넘어가지 않습니다.
→ 원인과 대처는 [`docs/troubleshootings/reusable/clipboard-writetext-loses-formatting.md`](docs/troubleshootings/reusable/clipboard-writetext-loses-formatting.md)

다음 경우에는 복사하지 않고 사유를 알립니다 — 마커가 없음 / 한쪽만 있음 / 순서가 뒤바뀜 /
두 쌍 이상 / 영역이 비어 있음. 특히 **빈 영역은 거부합니다.** 빈 클립보드가 조용히 나가면
그대로 스크럼에 붙기 때문입니다.

코드 블록과 frontmatter 안에 적힌 마커는 마크다운 예시로 보고 무시합니다.

### 스크럼(scrum) 영역 넣기

커서 위치에 빈 스크럼 영역(마커 한 쌍)을 넣습니다. 마커를 직접 칠 필요가 없습니다.
한 노트에 영역은 하나만 만들 수 있습니다.

## 동작 예시

`2026-08-31` 노트에 이렇게 적어뒀다면:

```markdown
**[금일 예정 업무]**
- 업무 계획 :
	- 캐시 데이터 조회 API 개발
	- PR 리뷰 2건
- 이슈 사항 : x
- 협업 및 기타: x
```

다음 날 `2026-09-01` 노트에서 **전일 진행 업무 로드** 를 실행하면:

```markdown
**[전일 진행 업무]**          ← 이 섹션 본문만 교체됩니다
- 업무 계획 :
	- 캐시 데이터 조회 API 개발
	- PR 리뷰 2건
- 이슈 사항 : x
- 협업 및 기타: x

**[금일 예정 업무]**          ← 그대로 둡니다
- 업무 계획 :
```

두 노트가 `Work/Daily/2026-08/` 과 `Work/Daily/2026-09/` 로 **다른 폴더에 있어도**
찾아냅니다.

## 커맨드

| 커맨드 | 설명 |
|---|---|
| 전일 진행 업무 로드 | 직전 데일리 노트의 금일 예정 업무를 현재 노트의 전일 진행 업무로 가져옵니다. |
| 데일리 노트 템플릿 삽입 | 커서 위치에 업무 양식 본문을 삽입합니다. |
| 스크럼(scrum) 내용 복사 | 스크럼 영역 안의 내용만 클립보드에 복사합니다. 서식(HTML)과 마크다운 원문을 함께 담습니다. |
| 스크럼(scrum) 영역 넣기 | 커서 위치에 빈 스크럼 영역(마커 한 쌍)을 넣습니다. |

## 설정

| 항목 | 기본값 | 설명 |
|---|---|---|
| 전일 섹션 이름 | `전일 진행 업무` | 내용을 채워 넣을 섹션 |
| 금일 섹션 이름 | `금일 예정 업무` | 이전 노트에서 읽어올 섹션 |
| 데일리 노트 루트 폴더 | (비움) | 전일 노트를 찾을 범위. 비우면 현재 노트의 부모 폴더를 쓰되, 부모가 `YYYY-MM` 형태의 월 폴더면 한 단계 위를 씁니다. |
| 본문 템플릿 | inno 업무 양식 | 템플릿 삽입 커맨드가 넣을 본문 |

본문 템플릿에서 쓸 수 있는 변수:

| 변수 | 치환값 |
|---|---|
| `{{previousSection}}` | 전일 섹션 이름 |
| `{{todaySection}}` | 금일 섹션 이름 |
| `{{date}}` | 오늘 날짜 (`YYYY-MM-DD`) |

## 설치

`main.js` 와 `manifest.json` 을 Vault 의 플러그인 폴더에 복사한 뒤
설정 > Community plugins 에서 활성화합니다.

```
<vault>/.obsidian/plugins/inno-daily-log/
├── main.js
└── manifest.json
```

소스에서 직접 빌드하려면:

```bash
npm install && npm run build   # main.js 생성
```

생성된 `main.js` 와 `manifest.json` 을 위 경로로 복사한 뒤 Obsidian 을 다시 로드합니다.

## 문제 해결

| 증상 | 원인 |
|---|---|
| "현재 노트 파일명에서 YYYY-MM-DD 날짜를 찾을 수 없습니다" | 파일명에 날짜가 없음 |
| "이전 데일리 노트에서 '금일 예정 업무'를 찾을 수 없습니다" | 이전 노트에 해당 섹션이 없거나 내용이 비어 있음. 루트 폴더 설정 확인 |
| "현재 노트에서 '전일 진행 업무' 섹션을 찾을 수 없습니다" | 현재 노트에 섹션 제목이 없음. 템플릿 삽입 커맨드 사용 |
| "이미 …가 반영되어 있습니다" | 이미 같은 내용. 정상 |
| "스크럼 영역 표식이 없습니다" | 노트에 마커가 없음. **스크럼(scrum) 영역 넣기** 커맨드 사용 |
| "스크럼 영역은 시작·끝 표식 한 쌍이어야 합니다" | 마커가 한쪽만 있거나, 순서가 뒤바뀌었거나, 두 쌍 이상 있음 |
| "스크럼 영역이 비어 있습니다" | 마커 사이에 내용이 없음. 빈 클립보드를 만들지 않으려고 막습니다 |
| "표식이 이미 있습니다" | 한 노트에 스크럼 영역은 하나만 만듭니다 |
| "클립보드 쓰기에 실패했습니다" | Obsidian 창이 비활성 상태. 창을 클릭해 활성화한 뒤 다시 실행 |

기여 규칙과 AI 작업 지침은 `CLAUDE.md` 에 있습니다.

## 개발

```bash
npm install      # 의존성 설치
npm run dev      # 개발 모드 (watch)
npm run build    # 타입 체크 + 프로덕션 빌드
npm test         # 단위 테스트
```

테스트는 순수 함수(`src/daily-log.ts`, `src/template.ts`, `src/scrum.ts`, `src/markers.ts`)만
다룹니다.
커맨드 동작과 설정 화면은 Obsidian API 목이 없어 자동 테스트 대상이 아니며,
실제 Vault 에서 수동 확인해야 합니다.
