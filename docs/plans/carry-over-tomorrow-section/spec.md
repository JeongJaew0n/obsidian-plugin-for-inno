# spec — 내일 이어서 할 것 이월

결정의 근거는 [`context.md`](context.md) 에 있다.

## 목표

`전일 진행 업무 로드` 를 실행하면, 전일 업무를 가져오는 김에 **전날 노트의
`내일 이어서 할 것`** 을 오늘 노트의 같은 섹션으로 옮긴다. 전날에 없으면 아무것도 안 한다.

그 전에, 새 템플릿 배치에서 **전일 로드가 `### 내일 이어서 할 것` 을 끌고 가는 버그**를 고친다.

## 범위

### 1. 버그 수정 — 섹션 끝에 heading 추가 (별도 커밋 `fix`)

`**[이름]**` 섹션의 본문 끝 판정에 **마크다운 heading(`#`~`######`)** 을 더한다.

```
지금:  다음 **[제목]**  |  ---
이후:  다음 **[제목]**  |  ---  |  # heading
```

- 기존 노트 200개 전수 확인 결과 영향받는 4개는 모두 이 수정이 맞는 쪽이다 (context.md).
- 새 기능과 독립적으로 가치가 있다. 먼저 넣고 따로 커밋한다.

### 2. heading 섹션 파싱 (`daily-log.ts`, 순수 함수)

| 함수 | 하는 일 |
|---|---|
| `extractHeadingSection(content, name)` | `# ~ ###### name` 섹션 본문. 없으면 `null` |
| `fillHeadingSectionIfEmpty(content, name, body)` | 비어 있을 때만 채운 문자열. 결과를 `"missing" \| "occupied" \| "filled"` 로 구분해 돌려준다 |

본문 규칙:

- 제목 줄은 NBSP·앞뒤 공백을 정규화해 **텍스트로** 비교한다. heading 레벨은 가리지 않는다.
- 본문 끝 = `---` · `**[..]**` · **자기와 같거나 높은(숫자가 작거나 같은) 레벨의 heading** · 파일 끝.
  하위 heading(`###` 아래의 `####`)은 본문에 포함한다.
- 한 줄짜리 `%% ... %%` 주석은 뺀다 (기존 `dropCommentOnlyLines` 재사용).
- 앞뒤 빈 줄은 잘라서 비교·추출하고, 채울 때는 **목적지의 앞뒤 빈 줄을 보존**한다
  (기존 `replaceSection` 과 같은 규칙).
- "비어 있음" = 위 규칙을 적용한 뒤 공백만 남는 것.

### 3. 이월 로직 (`daily-log.ts`, 순수 함수)

```ts
carryOverTomorrowSection(sourceContent, targetContent)
  → { content: string; result: "no-source" | "no-target" | "occupied" | "carried"; lines: number }
```

| 전날(소스) | 오늘(목적지) | 결과 | 오늘 노트 |
|---|---|---|---|
| 섹션 없음 / 비었음 | — | `no-source` | 그대로 |
| 있음 | 섹션 없음 | `no-target` | 그대로 (만들지 않는다) |
| 있음 | 이미 내용 있음 | `occupied` | 그대로 (덮지 않는다) |
| 있음 | 비었음 | `carried` | 채운다 |

- 소스 노트 = **전일 진행 업무를 가져온 바로 그 노트.** 더 거슬러 찾지 않는다.
- 섹션 이름 상수 `DEFAULT_CARRY_OVER_SECTION = "내일 이어서 할 것"`. 설정 항목 아님.

### 4. 연결 (`main.ts`)

- `loadPreviousWork` 가 `findPreviousWork` 로 고른 **같은 파일**의 원문을 이월에도 쓴다.
  지금은 본문만 돌려주므로, 소스 원문도 함께 돌려주게 바꾼다 (디스크를 두 번 읽지 않는다).
- 전일 섹션 교체와 이월을 **한 번의 `vault.process` 안에서** 처리한다. 두 번 쓰면 사이에
  에디터 변경이 끼어들 수 있다. `process` 가 없을 때의 `read`→`modify` 폴백 분기는 유지한다.
- 이월은 **부속 단계**다. 이월 결과가 무엇이든 전일 로드의 성공·실패를 바꾸지 않는다.

알림 — 한 번에 하나로 합쳐 띄운다.

| 전일 | 이월 | 알림 |
|---|---|---|
| 불러옴 | `carried` | `2026-09-28의 업무를 불러왔습니다. 내일 이어서 할 것 5줄도 가져왔습니다.` |
| 불러옴 | `no-source` | `2026-09-28의 업무를 불러왔습니다.` (이월은 조용히) |
| 불러옴 | `occupied` | `… 내일 이어서 할 것은 이미 적혀 있어 그대로 뒀습니다.` |
| 불러옴 | `no-target` | `… 이 노트에 '내일 이어서 할 것' 섹션이 없어 가져오지 않았습니다.` |
| 이미 반영 | (위와 같음) | 기존 문구 + 이월 결과 |
| 전일 섹션 없음 | — | 기존 문구 그대로. **이월도 하지 않는다** (템플릿이 아닌 노트로 본다) |

`no-source` 를 조용히 두는 이유 — 요청이 "없으면 안 가져온다" 이고, 매일 뜨면 소음이 된다.

### 5. 내장 템플릿 동기화 (`template.ts`)

`DEFAULT_BODY_TEMPLATE` 에 Vault 템플릿과 같은 위치로 섹션을 넣는다.

```
**[금일 예정 업무]**
...
(스크럼 끝 마커 자리)

### 내일 이어서 할 것


---
# 일 순서
```

스크럼 마커는 **넣지 않는다** — 지금 내장 템플릿에도 없고, 이번 범위가 아니다.
