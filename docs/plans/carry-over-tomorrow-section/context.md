# context — 내일 이어서 할 것 이월

## 원 요청 (2026-09-29)

> 템플릿에 '내일 이어서 할 것' 이 생겼거든? 이걸 전날에 있으면 가져오고, 없으면 안가져오는
> 기능. 일단 분석 설계 ㄱㄱ
>
> 템플릿 위치: `Work/Daily/템플릿(template) inno.md`

## 조사로 확인한 사실

### 새 섹션은 기존 섹션과 형식이 다르다 [확정]

템플릿 원문 (구조만):

```
 7: %% inno-scrum:start %%
 8: **[전일 진행 업무]**
13: **[금일 예정 업무]**
17: %% inno-scrum:end %%
19: ### 내일 이어서 할 것        ← 마크다운 heading (h3)
22: ---
23: # 일 순서
```

- 기존 두 섹션은 `**[이름]**`(볼드 대괄호)이고, 새 섹션은 **마크다운 heading** `### 이름` 이다.
  지금 파서(`normalizeSectionHeading`)는 `**[이름]**` 만 안다 → 그대로는 못 찾는다.
- 스크럼 영역(7~17행) **밖**에 있다. 스크럼 복사에는 안 들어간다. 의도된 배치로 본다.

### 이미 쓰이고 있다 — 같은 섹션으로 굴려 넘긴다 [확정, 표본 1쌍]

새 섹션이 있는 실제 노트는 `2026-09-28`, `2026-09-29` 두 개. 둘 다 본문은 목록(`- `)이고
`---` 에서 끝난다.

09-28 의 `내일 이어서 할 것` 항목 5개가 09-29 의 **같은 `내일 이어서 할 것` 섹션에 5/5 그대로**
있다. `금일 예정 업무` 로 옮긴 것이 아니다. 사용자는 이 섹션을 **매일 앞으로 굴려 넘기는
목록**으로 쓰고 있다 → 목적지는 오늘 노트의 같은 이름 섹션이다.

표본이 한 쌍뿐이라는 점은 남겨둔다.

### 지금 코드에 잠복 버그가 있다 [확정]

섹션 본문의 끝은 다음 `**[제목]**` 이나 `---` 로만 판단한다(`daily-log.ts` `findSectionRange`).
새 템플릿 배치에서 `금일 예정 업무` 와 `---` 사이에 `### 내일 이어서 할 것` 이 끼면서,
**금일 본문이 heading 을 지나 `---` 까지 늘어난다.**

실제 노트에 실제 코드(`extractSection`)를 돌린 결과 (내용 미출력, 판정만):

```
2026-09-28 Abraxas.md: 금일 본문 15줄, '내일 이어서 할 것' 포함=true (10번째 줄부터 5줄이 딸려옴)
2026-09-29 Abraxas.md: 금일 본문 17줄, '내일 이어서 할 것' 포함=true (12번째 줄부터 5줄이 딸려옴)
```

즉 지금 `전일 진행 업무 로드` 를 돌리면 **`### 내일 이어서 할 것` 제목과 항목까지 전일
진행 업무로 끌려간다.** 실제 노트에는 아직 박히지 않았다 (09-29 에 제목 1회, 제자리).

**새 기능의 전제 조건이다.** 이걸 먼저 고치지 않으면 새 기능이 가져오기도 전에 기존 로드가
같은 내용을 엉뚱한 곳에 넣는다.

### heading 에서 끊어도 기존 노트가 깨지지 않는다 [확정, 전수]

데일리 노트 200개를 전수로 훑어, `전일`/`금일` 섹션 본문 안에 heading 이 든 노트를 찾았다.

```
200개 중 4개
   '내일 이어서 할 것': 2회   (09-28, 09-29)
   '논의가 필요한 것': 1회    (08-18)
   '낼 할거': 1회             (09-21)
```

네 경우 모두 사용자가 **섹션 뒤에 따로 붙인 별도 주제**다. `낼 할거` 는 사실상 이 기능의
전신이다. heading 에서 끊는 쪽이 사용자 의도에 맞는 해석이고, 지금 동작이 오히려 틀렸다.

### 템플릿이 두 벌이고 이미 갈라졌다 [확정]

- Vault 템플릿 `Work/Daily/템플릿(template) inno.md` — 코어 `templates`·`daily-notes` 가
  활성이라 이쪽이 실사용 경로로 보인다. **새 섹션 있음.**
- 플러그인 내장 `DEFAULT_BODY_TEMPLATE` (`template.ts`) — `데일리 노트 템플릿 삽입` 커맨드가
  쓴다. **새 섹션 없음.**

내장 템플릿으로 만든 노트에는 이월 목적지가 없다.

## 기각한 대안

- **목적지를 `금일 예정 업무` 로** — 실측이 반대다. 사용자는 같은 섹션으로 옮겨 적었다.
- **"전날" 을 바로 앞 날짜 노트로** — 주말·휴일 빈 노트에서 끊긴다 (D2).
- **없으면 더 과거에서 찾기** — 요청이 명시적으로 "없으면 안 가져온다" 다. 일주일 전 할 일이
  갑자기 되살아나는 것도 틀린 동작이다.
- **오늘 섹션을 항상 덮어쓰기** — 전일 섹션과 일관되지만, 사람이 쓰는 섹션을 지운다 (D5).
- **이어 붙이기(병합·중복 제거)** — 같은 항목이 표현만 조금 달라도 둘 다 남는다. 판정 규칙이
  복잡해지는 것에 비해 얻는 게 적다.
- **별도 커맨드** — 가능하지만 매일 아침 두 번 누르게 된다. D4 가 [가정] 인 이유다.
